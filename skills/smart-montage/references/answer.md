# 混剪 Brief 生成与修改

`talking_mixed_cut` 与 `material_mixed_cut` 都使用原会话和 `--brief-id` 生成。`--answer` 可省略；省略时使用当前 Brief，不新增空字段，也不要求素材分支提供口播视频。

当前 `--answer` 用于口播分支的下列编辑字段。素材分支省略 `--answer`；主题、文案、选材、时长、脚本或音色等调整通过更新分析要求完成：在原会话重新分析完整素材，展示并确认新 Brief 后生成。两种分支按各自的调用方式提交修改。

| 字段 | 值 | 约束 |
|---|---|---|
| `a_roll_media` | 媒体对象数组 | 至少一个，全部为真实视频 |
| `b_roll_media` | 媒体对象数组 | 图片或视频；空数组明确清空补充画面 |
| `target_duration` | JSON 数字 | 5–180 秒生成目标 |

媒体对象只含 `short_id` 与 `kind`，用于选择当前方案已经分析的素材；ID 与类型取自真实分析结果或同会话历史。对象不得包含 URL、文件路径或推测 ID。返回摘要的 `a_roll_short_ids/b_roll_short_ids` 不能直接用作答案字段。新增或替换源素材时，先按平台说明下载远程原资源，在原会话重新分析完整本地素材列表并确认新 Brief，不先登记，也不把新 URL 塞入答案。

下方只展示形状，必须替换为当前方案素材的真实 ID 和真实类型；用户未要求修改的字段省略：

```json
{
  "b_roll_media": [{ "short_id": "实际补充图片ID", "kind": "image" }],
  "target_duration": 45
}
```

直接传参时，将完整对象序列化为单个 `--answer` 参数并正确转义。复杂答案可使用参数文件：将会话、`briefId` 和上述 `answer` 对象写入同一请求 JSON，`answer` 不序列化为字符串，也不额外传业务 flags。仅检查或排查输入时按需追加 `--validate-only --json`。两种形式均不接受修改只读口播原文、切换分支、任意后端字段或素材混剪脚本和音色。
